# Windows 关闭窗口与托盘驻留

## 产品规则

- 仅 Windows 的“关闭窗口时隐藏到托盘”设置控制普通窗口关闭行为。开启时，点击关闭按钮或使用关闭窗口快捷键均隐藏该窗口；即使它是最后一个窗口、当前没有运行或排定的任务，也保持应用运行。
- 托盘“打开”恢复原窗口。隐藏窗口不销毁窗口、Local Host 或正在运行的任务，也不额外启动后台进程。空闲 scheduler 是否自退只由排定工作决定，不参与窗口关闭决策。
- 关闭该设置后，关闭非最后一个窗口会销毁该窗口；关闭最后一个窗口走现有退出及运行中任务确认流程。托盘“退出”、应用显式退出与强制退出不被隐藏逻辑拦截。
- macOS 使用独立的 Dock/窗口关闭处理；本设置不改变 macOS 或 Linux 行为。

## 状态所有者与事件顺序

- 设置由 SettingService 持久化。Desktop Main 启动时读取设置，并在设置变更后通过现有 `syncAppSettings` 通道即时更新 Main 内的 `closeToTrayOnWindows` 值；Renderer 的开关只呈现和提交该设置。
- Desktop Main 拥有窗口关闭与应用退出决策。scheduler 只拥有排定工作和自身空闲退出，不提供托盘驻留条件。
- 当前构建彻底禁用闲时任务；scheduler 的待触发工作和自退判断只包含普通 cron 自动化，旧闲时任务行不能使进程常驻。

```text
设置写入 → SettingService 持久化 → syncAppSettings → Main 更新 closeToTrayOnWindows
普通关闭 → Main close handler → Windows 且开关开启 → hide + preventDefault → 托盘打开时复用窗口
显式退出 → Main 标记 explicitQuit → before-quit 确认 → 清理 Host/窗口 → 退出
                                               └→ 用户取消：清除 explicitQuit，保留后续普通关闭的托盘语义
scheduler 空闲自退 ──────────────────────────────── 与关闭决策无关
```

## 验收场景

1. Windows 开关开启、无运行或排定任务：关闭最后窗口后应用仍在托盘，托盘“打开”恢复同一窗口和工作区。
2. Windows 开关开启、有运行中任务或排定任务：关闭最后窗口隐藏，任务继续执行；关闭其他窗口也隐藏。
3. Windows 开关关闭：关闭非最后窗口销毁该窗口；关闭最后窗口进入原有退出流程。
4. 托盘“退出”即使开关开启也完整退出；有运行中任务且取消退出确认时应用保留，此后普通关闭仍隐藏到托盘。
5. 静态核对：关闭判断不读取 scheduler 状态；空闲 scheduler 自退与按需唤醒路径保持原样；没有新增进程、轮询、遥测或重复状态。
